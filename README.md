# pdf-rag — Гибридный RAG-поиск по документам

Векторный поиск (ChromaDB + Ollama) + BM25 + FlashRank reranker + фильтр по продукту.  
Всё локально, без облаков. Все операции через HTTP-эндпоинты.

## Быстрый старт

```bash
chmod +x setup.sh
./setup.sh            # установка .venv + зависимостей + проверка Ollama
./setup.sh --systemd  # то же + установка systemd-сервиса
```

Перед запуском положи свои PDF, DOCX, PPTX в `pdf-rag/data/pdfs/`.

Сервер встанет на порту 11436. После первого запуска проиндексируй документы:

```bash
cd pdf-rag && .venv/bin/python src/ingestion_hybrid.py \
    --product "Название продукта" \
    --summary "Краткое описание"
```

## Поиск

```bash
curl 'http://localhost:11436/search?query=ваш+запрос'
curl 'http://localhost:11436/search?query=запрос&product=Название+продукта'
curl 'http://localhost:11436/search?query=запрос&k=20'
```

## Добавление документов

Через HTTP:
```bash
curl -X POST http://localhost:11436/upload -F "file=@/путь/к/файлу.pdf"
curl -X POST http://localhost:11436/ingest \
  -H "Content-Type: application/json" \
  -d '{"product": "Название", "summary": "Описание"}'
```

## Подключение к агенту

После развёртывания сервера любой ИИ-агент (Hermes, OpenAI Codex, Claude Code, самописный Telegram-бот) может искать и добавлять документы через HTTP — shell не нужен.

### Настройка агента

Укажи в промпте или SOUL.md агента адрес сервера и формат запросов:

```
Поиск документов: curl -s "http://localhost:11436/search?query=${вопрос}"
Загрузка нового документа: curl -X POST http://localhost:11436/upload -F "file=@путь/к/файлу"
Инкрементальная индексация: curl -X POST http://localhost:11436/ingest -H "Content-Type: application/json" -d '{"product": "Название", "summary": "Описание"}'
```

Ответ поиска — JSON с массивом `results[]`, каждый содержит `source` (имя файла), `text` (фрагмент), `product`, `rerank_score`. Агент формирует ответ на основе этих чанков.

### Что умеет агент через сервер

- Искать по всем документам с фильтром по продукту
- Загружать новые PDF/DOCX/PPTX — сервер сам проверяет дубликаты
- Запускать индексацию новых документов
- Проверять свой ответ на соответствие документам (`POST /validate`)
- Получать список файлов и статистику индекса (`GET /files`, `GET /status`)

Агент может быть любой — Telegram, CLI, web. Достаточно разрешить ему `curl` к localhost.

## Требования к серверу

### Минимальные (для запуска с уже проиндексированной базой до 500 документов)

| Компонент | Минимум | Пояснение |
|-----------|---------|-----------|
| **RAM** | 8 GB | 4 GB — search_server (ChromaDB + FlashRank целиком в памяти) + 2 GB — ОС + 2 GB — запас |
| **CPU** | 2 ядра, x86_64 | Процессор нужен только под `pypdf`/`docx`/`pptx` на чтении файлов и FlashRank на CPU. Сами эмбеддинги на runtime не нужны |
| **GPU** | Не обязателен | Для runtime GPU не используется. Нужен только для индексации (см. ниже) |
| **SSD** | 50 GB свободно | 5 GB — проект + код, 30 GB — под индексную базу (ChromaDB + BM25 ~300 MB на 400 доков + сырые PDF), 15 GB — запас. Учти: архив базы для переноса ~4.5 GB |
| **Ollama** | Не нужен на runtime | Эмбеддинги предвычислены при индексации. search_server работает без Ollama |

### Комфортные (для регулярной индексации и расширения)

| Компонент | Комфортно | Пояснение |
|-----------|-----------|-----------|
| **RAM** | 16 GB | 8 GB — search_server (база 2000+ документов), 2 GB — Ollama при индексации, 4 GB — ОС, 2 GB — запас |
| **CPU** | 4 ядра | 2 ядра — search_server + ОС, 2 ядра — распараллеливание извлечения текста и BM25 при индексации |
| **GPU** | **NVIDIA 6+ GB VRAM** (CUDA) | Эмбеддинги считаются через Ollama на GPU. На RTX 3060 12GB ~10 минут на 8000 чанков. Без GPU — генерация через CPU в 10-30× дольше (часы для 400 доков) |
| **SSD** | 200 GB | 50 GB — база под 2000+ документов, 50 GB — tmp под архивацию/реиндексацию, 100 GB — запас |
| **Ollama** | Версия 0.5+ | Запускается только на время индексации. Ресурс при индексации: +1-2 GB RAM + ~0.5 GB VRAM на модель nomic-embed-text |

### Потребление компонентов (замерено на реальной системе)

| Компонент | RAM | CPU | GPU | Диск |
|-----------|-----|-----|-----|------|
| **search_server** (FastAPI + ChromaDB + BM25 + FlashRank) | **800 MB** (база 400 файлов / 8000 чанков) | 0.3% idle | 0 | 5.3 GB |
| **Генерация эмбеддингов** (индексация, batch 32) | +1-2 GB (временный, на время индексации) | 1-2 ядра | **~0.5 GB VRAM** | 0 |
| **FlashRank** (ms-marco-MiniLM-L-12-v2) | входит в 800 MB search_server | CPU-only | 0 | **6.4 GB** кеш huggingface |
| **Ollama daemon** (в простое) | ~200 MB | 0% | ~200 MB VRAM | 300 MB (модель) |
| **ChromaDB** | входит в 800 MB (держит всё в памяти) | 0% | 0 | **380 MB** (индекс) |
| **BM25** | входит в 800 MB | 0% | 0 | ~20 MB (pkl) |

### Если база растёт

| Размер коллекции | RAM search_server | Диск (ChromaDB) | Время индексации (GPU) |
|------------------|-------------------|-----------------|------------------------|
| 500 документов / 10k чанков | ~1 GB | ~0.5 GB | ~15 мин |
| 2000 документов / 40k чанков | ~2-3 GB | ~2 GB | ~1 час |
| 10000 документов / 200k чанков | ~8-10 GB | ~10 GB | ~5 часов |

## Технические детали

- Поиск: ChromaDB (n_results=30) + BM25 (n_results=30) → RRF fusion → FlashRank reranker
- Эмбеддинги: nomic-embed-text через Ollama, метрика cosine
- Чанкование: 768 слов, overlap 128
- Дедупликация по SHA256 при загрузке
- Все операции доступны через HTTP — shell не требуется

### Модель эмбеддингов

**Текущая:** `nomic-embed-text` (v1, ~137M параметров, 768 dim)

**Особенности:**
- **Английский** — модель обучена только на английских текстах. Русские, китайские и другие языки дают некорректные вектора — поиск по ним будет случайным.
- **Требует Ollama** — эмбеддинги генерируются через Ollama (`llama_index.embeddings.ollama.OllamaEmbedding`).
- **Не нужна на runtime** — эмбеддинги предвычислены при индексации. Ollama запускается только при добавлении новых документов.
- **512 токенов контекст** — чанки длиннее обрезаются (сейчас чанки по 768 слов, укладываются).
- **Префиксы не требуются** — в отличие от мультиязычных аналогов, nomic-embed-text не нуждается в `search_query:` / `search_document:` префиксах.

**Если нужен русский / мультиязычный поиск:**

| Модель через Ollama | Языки | Размер | Особенности |
|---------------------|-------|--------|-------------|
| `nomic-embed-text-v2-moe` | 100+ языков (**ru**, de, fr, zh, ar…) | 475M (305M активных, MoE) | Прямая замена, 768 dim |
| `bge-m3` | 100+ языков | 567M | Гибкая размерность, популярная |
| `granite-embedding-278m-multilingual` | 50+ языков | 278M | Лёгкая |
| `qwen3-embedding` | 100+ языков | от 0.6B | Свежая, дороже |

**При смене модели:**
1. Поменять `model_name` в `hybrid_search.py` и `ingestion_hybrid.py`
2. Запустить полную переиндексацию — старые вектора несовместимы с новой моделью
3. FlashRank (`ms-marco-MiniLM-L-12-v2`) — тоже английский. Для русского реранжинга нужна замена на `BAAI/bge-reranker-v2-m3`

**Ресурсы при индексации:**
- RAM: ~1-2 ГБ на генерацию эмбеддингов (batch 32)
- GPU: обязательно для скорости (без GPU — часы вместо минут)
- Время: ~10-30 минут на 400 документов / 8000 чанков
